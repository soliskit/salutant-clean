# Credit-protected publication

The publishing procedure checks every candidate commit and all parents before uploading objects. Both author and committer must be David Solis <doze.inept.0n@icloud.com>. Messages require Why, How and Tags sections and must pass the retained project message checks.

The section requirement in the preceding paragraph applies to new commit objects only. Values may appear on the same or following lines. A fixed reviewed repository-bound manifest of six existing exact objects preserves only their message formatting. Every message still passes project-message and prohibited-credit checks, and every ancestor retains raw-object, header, author and committer validation.

Existing project hooks stay active. The local installer uses genuine project pre-commit and commit-msg hooks and a full-history pre-push audit. The additional validator binds the exact repository, branch, candidate and predecessor. Unknown state stops publication.

The production check is Credit ancestry v2-e4. A repository-selected installation token publishes exact admitted objects and that check before an ordinary nonforce push. Existing main protection remains unchanged when separate all-branch rules are added.

Signed or noncanonical commit headers stop rather than being rewritten. A stopped upload can leave public Git objects reachable even when no branch moved. Rollback restores only the exact recorded installation and retains unexpected later edits for inspection.
